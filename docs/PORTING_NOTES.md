# Porting notes: Bloody Roar 4 [Analog Stick Mod] (PAL, SLES_518.77) with PS2Recomp

Technical record of what it took to run Bloody Roar 4 natively on Windows, with the same method as the NBA
Street V3 port (and its runtime) and the DBZ Budokai Tenkaichi 4 port's GS host. Base path:
`C:\BloodyRoar4Recomp`. Never commit the ISO, the ELF or any game data.

## 1. Architecture

```
 ps2EntryRunner.exe (game recompiled to x64 C++)                pcsx2-gsrunner.exe -live (PCSX2 d073d75 + patch)
 +----------------------------------------------+             +-------------------------------------------+
 | EE: the game's recompiled code (src\runner)    |  shared-    | VIF1 + microVU1 (x86 VU recompiler)        |
 | kernel / IOP / SPU2 / CD / MPEG (HLE + IOP)    |  memory     | GIF unit (PATH1/2/3)                       |
 | Hudson SSM on the IOP, EE RPC servers for it   |  ring v2 -> | GS on Vulkan / D3D12, 6x, DLSS / FSR, F1   |
 | PATH3 packets inside the VIF1 stream (DIRECT)  | <- readback | window, keyboard, controller (XInput)      |
 +----------------------------------------------+             +-------------------------------------------+
```

- The ring is the DBZ host's **version 2**: GS -> EE read-backs (`StoreImage`) are answered by PCSX2, the game
  serial comes from `PS2X_LIVE_SERIAL` (PCSX2's per-game GS fixes), the window title from `PS2X_LIVE_TITLE`, the
  host runs without a console, and the F1 menu's 60 fps request is published back (`liveFps60Requested` /
  `publishLiveFps60`).
- **60 fps without a special mode:** the runtime generates VBlank at 60 Hz even though the disc is PAL (50 Hz),
  so the game runs at the speed of the NTSC version. The videos (25 fps) run at ~50 fps refresh.

## 2. Recompilation pipeline

| Path | What |
|---|---|
| `game\iso\` | the extracted disc (`SLES_518.77` = the mod's ELF, SHA-256 `228548DA...BF83DCDB`) |
| `game\BloodyRoar4.iso` | hard link to the ISO (the runtime reads disc sectors from it: `PS2X_CD_IMAGE`) |
| `game\config\` | Ghidra's `functions.csv`; `config.toml` = Ghidra + `ps2_analyzer`'s SCE signatures + `gap_entries.txt` |
| `game\output\` | C++ generated by `ps2_recomp` (copied to `PS2Recomp\ps2xRuntime\src\runner`) |
| `game\overrides\bloody_roar4_overrides.cpp` | the game's own code: analog mod, 16:9, CD image, bindings |

1. Ghidra headless (`tools\ghidra_br4.cmd`, R5900 processor, PS2Recomp's `ExportPS2Functions.java`, ~3 min)
   -> `config.toml` + `functions.csv` (5068 functions, 55 stubs).
2. `ps2_analyzer` on the ELF -> `config.analyzer.toml` (SCE library signatures in this stripped ELF).
3. `fix_functions_csv.ps1` (impossible function ends Ghidra leaves) and `find_gap_entries.ps1` (code outside any
   function: entry points).
4. `merge_config.ps1` -> `config.toml`: 301 stubs, 680 entry points.
5. `ps2_recomp config.toml` (~1 min) -> `fix_sqrt_s.ps1`, `fix_branch64.ps1`, `fix_cop0_count.ps1` -> copy the
   `.cpp` to `ps2xRuntime\src\runner`, the `.h` to `ps2xRuntime\include`, plus the override.
6. `tools\configure.cmd` + `tools\build_runner.cmd` (unity build, ~8 compilers on 32 GB).

Steps 1-4 are committed (`game\config`); a player's install starts at step 5.

## 3. The Analog Stick Mod

The mod patches the game's own copy of libpad's `scePadRead` (0x2DA7D0, identified by matching NBA Street V3's
`scePadRead` word for word): the 2nd instruction becomes `j 0x000FD050` and the final `jr ra` becomes
`j 0x000FD05C`, code outside the ELF that post-processes the pad data. That code is not on the disc as such, so
it cannot be recompiled. Instead:

- 0x2DA7D0 is bound to the runtime's `scePadRead` (HLE), and `padReadWithStick` wraps it: while the pad
  reports analog mode (0x73 / 0x79), the left stick also presses the D-pad, 8 directions (an axis counts when
  it is at least half of the dominant one, ~26.6 degrees), beyond a dead zone of 48.
- `PS2X_PAD_ANALOG=1` (runtime, `Pad.cpp`) puts the pad in analog mode from the start; on a console the
  player has to press ANALOG.
- `PS2X_BR4_STICK=0` turns the stick mapping off, `PS2X_BR4_STICK_DEADZONE=<0..127>` changes the dead zone.

## 4. 16:9

PCSX2's widescreen patch for SLES-51877 (by ElHecht) writes the projection's horizontal scale at 0x0060EC20
(0x3FDA2E04 -> 0x3FA3A283). The override applies it on every `sceGsSyncV` (0x2C9120), only while that address
holds the original value. It needs `AspectRatio = 16:9` in the GS host's ini. `PS2X_BR4_WIDESCREEN=0` turns
it off (the launcher's 4:3 option, with the `_4x3` presets).

## 5. Runtime changes (on top of the NBA Street V3 runtime)

- **Live ring version 2** (the DBZ host's): `StoreImage` read-backs answered by PCSX2, `PS2X_LIVE_SERIAL`,
  console-less host, 60 fps request from the F1 menu.
- **`bytesForPixels`:** PSMCT24 / PSMZ24 are 3 bytes per pixel (the bug that froze DBZ at the start of fights).
- **`PS2X_PAD_ANALOG=1`** (forced analog mode) and **`PS2X_FFMPEG_LOCAL_ZIP`** (configure without downloading
  FFmpeg again).
- **Game override:** the game runs its own malloc over the whole `SetupHeap` range (0x41CF50 to the end of RAM).
  Without a private runtime region, the runtime's GS packets (`sceGsPutDispEnv`...) landed on the game's first
  heap block, a list of handlers walked by 0x0028D990, which then called 0. Now 64 KB at the top is reserved
  for the runtime (`setRuntimeHeapReserve`; it uses a few hundred bytes there). It used to be 1 MB, and that
  left the game heap too tight: with Alice as the opponent, malloc failed for `chr/ali/0010_ps2.dff`
  (0x39340 bytes), the loader fell back to the CD path and retried `\CHR\ALI\0010.DFF` forever on LOADING. The two unnamed `sceCdSearchFile` copies at 0x2D8730 (`_sceCdSearchFile`,
  binds 0x80000597 like NBA's 0x004C6E60) and 0x2D8A48 (a 28-byte wrapper) are bound to the runtime's; left as
  guest code they spin forever in "bind RPC until cd->server != 0".
- **IOP -> EE RPC** (`iop_rpc.cpp`, `RPC.cpp`, `IopHost::findEeRpcServer` / `callEeRpcServer`): Hudson's SSM
  (the sound driver on the IOP) binds to the server 0x1001 that the game registers on the EE and asks it for the
  sound banks (function 0x40000000 = the EE does `sceSifSetDma` to the IOP). The IOP thread waits in `RpcWait`
  until the EE invocation finishes.
- **IOP `thvpool`** (CreateVpl / AllocateVpl / FreeVpl...) and the IOP heap from 0xA0000 (the SSM asks for
  512 KB + 2x288 KB).
- **IOP `sceCdRead`** (the SSM's BGM reads) served by the host with the game's LSNs (`readCdSectorsForIop`).
- **PSS videos:** the demuxer keeps the compressed video instead of refusing input (the audio is ahead in the
  PSS and the game syncs the pictures to the audio position); `rotateReadyQueue` brings time up to date
  (`RotateThreadReadyQueue` loops that yield to each other).
- **Textures / PATH3:** each MSKPATH3 window of a VIF1 list releases a single PATH3 GIF packet (BR4 uploads ~90
  textures per frame in one chain), and that PATH3 goes inside the VIF1 stream as DIRECT so the host's VU1
  (MTVU) cannot get ahead of it. `PS2X_PATH3_ONE_PACKET=0` / `PS2X_PATH3_VIA_DIRECT=0` go back to the old
  behaviour.
- **`sceGifPkAddGsAD` / `sceGifPkCloseGifTag` (HLE):** the DMA tag's qwc is added once, when the tag is closed,
  like the SDK does (it used to be counted twice and the video pictures never reached the GS).
- **Diagnostics:** `PS2X_IOP_RPC_LOG=n`, `PS2X_PATH3_TRACE=<s>`, `PS2X_GS_DUMP` alongside the live host.
- **`PS2X_WAVCAP=<file.wav>`:** records what goes to the audio device (16-bit stereo 48 kHz); `<file>.start` holds
  the wall clock of the first sample, so it can be muxed with a screen recording (`tools\record_video_dlss5.ps1`).

## 6. GS host

`pcsx2-gsrunner` built from PCSX2 `d073d75` + `patches\pcsx2.patch` (= NBA Street V3's `pcsx2.patch` + the DBZ
BT4 host patches `pcsx2-gsrunner-live-dbz.patch` and `pcsx2-gsrunner-dbz-windows.patch`), with PCSX2's own
`GameIndex.yaml` and `nvngx_dlss.dll` 310.9.1. Presets `gshost\br4*.ini`:

- `br4.ini`: Vulkan, 6x (3840x2688 internal, supersampling at 1440p), 16x anisotropic, FXAA, CAS 50,
  `NbaUpscaler = 2` (DLSS, FSR 1 without it; only acts when the internal image is smaller than the window),
  16:9, HD texture replacements on.
- `br4_dlss.ini`: the same at 2x (1280x1024 in PAL) so DLSS upscales to the screen.
- `_4x3` variants: `AspectRatio = 4:3` (no widescreen patch).
- **DLSS 5** (`gshost_dlss5\`, `br4_dlss_dx12.ini`): Direct3D 12 (`Renderer = 15`), 2x + DLSS, with ReShade
  (`dxgi.dll`), the RenoDX DLSS 5 add-on and NVIDIA's `nvngx_dlssnr.dll` (DLSS Neural Rendering) taken from DLSS 5
  Swapper. A separate copy of the host so the normal one never loads ReShade. F6 = neural pass on/off, Home =
  ReShade / add-on menu. DLSS (and so the neural pass) only runs when the window is larger than the 2x image.
- **DLSS on flat screens:** temporal DLSS uses motion vectors estimated on the GPU (block matching), the game's
  depth buffer and a "bias current colour" mask. On screens without game depth (menus, text, logos, videos) the
  block matching finds false matches in text and 2D fades and smeared the letters (worse with the DLSS 5 neural
  pass on top), so there the host now upscales frame by frame (no vectors, no history); 3D scenes keep temporal
  DLSS. `PS2X_DLSS_FLAT_MOTION=1` restores vectors on flat screens; `PS2X_DLSS_MOTION=0` turns them off everywhere.

## 7. Measurements (RTX 4090)

- Boot -> memory card (AUTO LOAD) -> HUDSONCI and OPENING videos -> title -> character select -> fight, with
  music (streamed BGM) and effects.
- `br4.ini` (6x, FXAA, CAS, 16:9): 59.8-60 fps internal, GPU 2-7 ms per frame.
- `br4_dlss.ini` in a 2560x1440 window: 59.4-60 fps, no stutter, `NVIDIA DLSS (640x960 -> 2526x1421)`.
- DLSS 5 at 1920x1080 with the neural pass: 57-60 fps.
